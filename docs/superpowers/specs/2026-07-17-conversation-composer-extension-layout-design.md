# 主会话扩展区与计划模式交互优化设计

## 目标

在不改变会话、发送、权限、表单、Todo、待发送和计划模式业务接口的前提下，降低主输入区同时出现多种扩展状态时的高度与视觉嵌套，保持输入框位置稳定，并让计划模式的入口和确认操作更贴近编辑行为。

## 信息架构

`ConversationComposer` 继续使用 `conversation-composer__dock` 作为唯一外框，内部从上到下分为：

1. 项目与分支上下文栏。
2. Todo/待发送共享扩展槽。
3. 计划就绪确认条（仅待确认时出现）。
4. 输入编辑器与底部工具栏。

权限询问和表单询问不进入上述文档流，而是锚定在共享扩展槽上方的真正悬浮层。悬浮层不参与 dock 高度计算，因此出现、切换或关闭时不会推动输入框。

## Todo 与待发送共享槽

- Todo 和待发送具有相同展示优先级，不再上下堆叠。
- 两类数据同时存在时，槽位顶部显示“待办”和“待发送”两个轻量标签及数量；默认选中待发送，避免未发送内容被忽略。
- 只有一类数据时只显示该类标题，不制造多余切换控件。
- 用户切换标签时保留各自折叠状态；共享槽本身仍可整体折叠。
- 待发送列表取消“容器内再嵌套独立卡片”的表现。条目使用连续列表和分隔线，失败状态通过轻量底色、状态文本和错误信息区分。
- 编辑、立即发送、重试和删除行为保持现状，不修改队列数据接口。

## 权限与表单悬浮层

- 悬浮层以 composer 的扩展槽为定位锚点，横向与 dock 内边界对齐，显示在 Todo/待发送槽的视觉上方。
- 权限与表单同时存在时纵向堆叠；若数据具备到达时间则按时间排序，否则采用稳定的固定顺序，避免渲染跳动。
- 每个悬浮项保留原有交互和内部层级，但取消与 dock 重复的厚重外框和过度阴影。
- 悬浮层设置可用高度上限，内容过长时仅内部滚动，不遮挡整个会话窗口。
- 悬浮项使用足够高的层级，但不覆盖项目/分支下拉、文件提及和斜杠菜单等临时交互层。
- 权限或表单出现、关闭以及焦点切换时，dock、编辑器与 textarea 的几何尺寸保持不变。

## 计划模式入口

- 移除当前占据输入框上方高度的 `plan-footer`。
- 进入计划模式后，在底部工具栏的 CLI 选择器旁显示“计划”轻量入口；非计划模式不显示。
- 桌面端悬停或键盘聚焦“计划”时展示“退出计划”和“执行计划”操作；移动端或不支持 hover 的环境点击后展开。
- 弹出操作具备明确的主次关系：执行为主操作，退出为次操作；支持 Escape 和点击外部关闭。
- 入口展开与收起不改变输入框高度，不使用缩放类动画。

## Agent 计划确认

- Agent 计划全文继续保留在现有右侧悬浮侧窗中，避免在主消息流重复渲染。
- 当计划生成完成并等待确认时，在输入框正上方显示轻量询问条，内容为“计划已就绪”和主操作“开始执行”。
- 确认条下方始终是可编辑输入框；用户直接输入并发送即表示继续调整计划，不再需要单独的“继续修改”按钮。
- “开始执行”继续调用现有计划执行路径；输入调整继续使用现有计划模式发送路径，不新增 IPC 或公共类型。
- 侧窗中的重复确认 CTA 移除，侧窗只承担全文查看、最小化和关闭。

## 视觉与响应式

- dock 仍只有一圈边框、圆角和阴影；共享槽内部使用分隔线建立层次。
- 待发送条目避免独立圆角卡片；悬浮询问可以保留小圆角和克制阴影，以表达其脱离文档流的层级。
- 亮色、暗色均使用现有 CSS 变量，不新增硬编码主题色。
- 窄屏时标签与标题截断，操作按钮保持可点击；悬浮层宽度跟随 dock，最大高度按视口计算。
- 尊重 `prefers-reduced-motion`，悬浮和弹出仅允许短距离透明度/位移反馈，不允许缩放或盒模型过渡。

## 状态与组件边界

- `ConversationComposer` 负责扩展槽、悬浮询问锚点、计划模式入口和计划就绪确认条的组合。
- `ConversationTodoPanel` 保持 Todo 展示职责，通过集成态 Props 适配共享槽，数据读取方式不变。
- 待发送继续使用现有队列数据与操作函数，仅调整展示结构和集成样式。
- `AgentPlanPane` 保留计划全文与窗口控制，移除其中重复的执行/修改 CTA。
- `MessageArea` 继续管理 Agent 计划侧窗显隐，并将“计划待确认”状态及执行入口传递给 composer 所在执行流；优先复用现有 store/composable，不新增跨层事件协议。

## 异常与可访问性

- 悬浮询问内容过长时内部滚动，操作区保持可见。
- 权限与表单同时存在时保持稳定 Tab 顺序；关闭上层后焦点回到合理的下一交互点或输入框。
- 计划入口可通过 Tab 聚焦，弹出菜单使用按钮语义和 `aria-expanded`。
- 队列条目在失败、编辑和普通状态下均保留可辨识文本，不只依赖颜色。

## 验收标准

1. Todo 与待发送同时存在时只占一个槽位，可切换且默认打开待发送。
2. 待发送展开后为连续列表，不再出现明显的卡片套卡片。
3. 权限和表单同时出现时真正悬浮并可依次操作，输入框 bounding box 不发生位移或缩放。
4. 计划模式入口显示在 CLI 选择器旁，悬停、键盘聚焦和窄屏点击均可访问退出与执行操作。
5. 计划待确认条位于输入框上方；开始执行可用，输入框仍可发送调整内容。
6. Agent 计划全文侧窗保留，但不再重复显示“继续修改 / 开始执行”CTA。
7. “全部扩展预览”会话能同时回显 Todo、待发送、权限、表单、计划和文件修改，并且输入框不被推出视口。
8. 亮色、暗色、1200px 桌面窗口和窄屏下无越界、重叠错误或不可点击操作。
9. 通过类型检查、目标 ESLint、相关单元测试和 Tauri MCP 实机验证；不执行 Tauri 打包。

## 非目标

- 不修改权限、表单、队列、Todo 或计划模式的数据协议。
- 不将项目/分支下拉、文件提及、斜杠命令菜单并入扩展槽。
- 不改变 Agent 计划正文的生成和持久化方式。
- 不清理当前工作区中与本任务无关的既有修改。
